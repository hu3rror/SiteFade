# 远程源规格（拉取、刷新、失败处理、合并）

Type: grilling
Status: resolved

## Question

远程源 = 通过 URL 拉取规则清单的来源。权限姿势已定（票 04：默认零 host 权限，CORS 失败时按源运行时授权）。待定：

1. **配置项**：每个源 = URL + 名称 + 启用开关 + 刷新间隔（可选定时的粒度：小时/天）+ 手动刷新按钮。确认？
2. **拉取时机**：添加源时立即拉一次；扩展启动时不主动拉（避免启动慢）——确认？
3. **失败处理**：拉取失败保留上次成功缓存，并显示"上次成功时间 + 失败原因"；连续失败 N 次（建议 3）自动停用该源防 stale。确认？
4. **内容防护**：拉到的内容逐行走与本地导入相同的校验（无效行跳过并计数），纯数据不执行。确认无需其它防护（如规则形态白名单）？
5. **多源合并**：规范化后天然去重；同一条规则既在手动又在远程时以手动为准（手动不可被远程覆盖，也不互删）。确认？
6. **缓存可见性**：设置页每源显示“上次成功时间 / 条数 / 状态”。确认这部分属于本票规格（不进 fog）？

## Answer

会话确认，6 条全部采纳。

1. **配置项**：每源 = URL + 名称（添加时从主机名预填、可改）+ 启用开关 + 自动刷新间隔（小时，最小 1 h，默认关 = 纯手动）+ 手动刷新按钮。自动刷新走 alarms。
2. **拉取时机**：添加源时立即拉一次；扩展启动不主动拉。**首拉失败也允许建源**（标“从未成功”状态，可改 URL 后手动重试）。浏览器关闭期间错过的自动刷新由 alarms 周期语义覆盖，不做补拉。
3. **失败处理**：失败保留上次成功缓存，展示“上次成功时间 + 失败原因”；原因分三类透出——网络错误 / HTTP 非 2xx / 解析失败（含超体积）。失败计数只记自动刷新；手动刷新成功即清零；连续失败 3 次自动停用（显示“连续失败”），需手动刷新成功才重新启用。
4. **内容防护**：远程内容逐行走与本地导入相同的校验（规则形态白名单、scheme 拒绝、长度/语法，见票 05）——校验即白名单；响应体上限 **2 MB**（超限计解析失败）；纯数据解析，从不执行。
5. **多源合并**：全局规范化去重；同一规则在多个远程源 → 保留一份、来源标记取首个引入的源；手动条目优先于远程（匹配时手动优先展示，删除时互不影响）；每源“条数” = 该源贡献的全局唯一规则数（去重后计数）。
6. **缓存可见性**：设置页每源显示“上次成功时间 / 条数 / 状态”；手动刷新带 loading 态与结果摘要（新增/无效）。属本票规格，不进 fog。

**影响面**：票 09 设置页的“远程源管理”按此规格呈现；拉取实现 = alarms + fetch + 按源授权（票 04）组合。
