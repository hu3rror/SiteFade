# 删除机制与匹配器选型（技术路线核心决策）

Type: grilling
Status: resolved
Blocked by: 01, 03, 04

## Question

事实已由票 01/03/04/05 查清：onVisited 是写后信号、deleteUrl 一次删该 URL 全部 visit、处理须幂等、仅需 history 权限；匹配器形态建议 = 主机后缀 Trie + 精确 URL 表；规则形态与匹配语义（精确 URL=scheme+host+path、主机忽略端口、IP/带端口条目进精确表、http/https 之外拒绝）见票 05；存储/同步结构与重建时机（上限 1000、防抖重建）见票 06；不再做定时/启动清扫（既定约束）。待定：

1. **主 hook 确认**：`history.onVisited` + `deleteUrl(url)`，幂等。接受？
2. **首次启用清扫**：既定约束是"不做清扫"——但扩展首次启用时历史里已存在的旧记录怎么处理？建议：首次启用时按当前清单做**一次性**清扫（否则装完对存量历史完全不生效）；此后不扫。做还是不做？
3. **删除失败降级**：deleteUrl 抛错/权限被撤销时的行为——静默忽略（推荐）还是记日志？失败率预期极低（URL 刚从 onVisited 来）。
4. **匹配器确认**：主机后缀 Trie（`*`/`+`/`.`/裸域名挂节点）+ 精确 URL HashMap；规则写入端防抖合并后重建（票 06 一并定）。接受？
5. **内部页无需处理**：`chrome://`、`about:`、扩展自身页面 URL 天然不会命中清单规则（规则语法票定了这些形态不可作为规则），确认无需特判。

## Answer

会话确认，5 条全部采纳。

1. **主 hook = `history.onVisited` + `deleteUrl(visitedUrl)`**，幂等。onVisited 已在写入后触发，无需队列等待；重定向链为每个目标各触发一次、逐个匹配逐个删；deleteUrl 一次删除该 URL 的全部历史访问（“不留任何痕”语义成立）。
2. **首次启用清扫 = 不做**（既定“不做清扫”约束完整落地）：装完只保护未来访问，存量历史保持原样，不引入批量重活。选项 (c) 的“设置页手动清理存量按钮”作为可选项**默认不做**，记入 fog。
3. **删除失败降级**：deleteUrl 出错静默忽略（不打断、不记日志）；popup 检测 `chrome.permissions.contains({permissions:['history']})`，权限缺失时提示“历史记录权限已关闭，停止保护”——避免装了个寂寞。
4. **匹配器确认**：主机后缀 Trie（`*`/`+`/`.`/裸域名挂节点）+ 精确 URL 表（scheme+host+path 归一；`file://` 也进此表）；**判定与删除分离**——访问 URL 归一化（host 小写、去端口、精确 URL 剥 query/hash）判命中，删除访问时的真实 URL（`deleteUrl(visitedUrl)`）；写入端防抖合并重建（票 06）。
5. **内部页无特判**：`chrome://`、`about:`、`chrome-extension://` 形态已被票 05 拒收、且本就不进历史；onVisited 对扩展自身页面不触发，无需过滤。

**影响面**：机制与匹配器至此定稿，为技术路线的核心。实现时匹配器可独立单测（规则→命中判定矩阵）；票 01 的 favicon/omnibox 残留属“社区共识”，实现阶段用原型验证。
