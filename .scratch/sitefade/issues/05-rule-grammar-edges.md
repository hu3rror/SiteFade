# 规则语法边界与导入规范化规格

Type: grilling
Status: resolved
Blocked by: (无)

## Question

四类形态（裸域名 / 精确 URL / `*` / `+` / `.` 通配符）与"每行一条纯文本 + `#` 注释 + 类型自动识别 + 规范化去重"已定（见 CONTEXT.md 与地图 Notes）。以下边界情形未定，逐条确认：

1. **IP 地址**：`127.0.0.1`、`192.168.1.1`、`[::1]` 当作裸域名处理（全站匹配）？精确 URL 里的 IP 照常解析？
2. **端口**：`example.com:8080` 是否合法？匹配时忽略端口（`example.com:8080` 命中 `example.com` 规则）还是仅当规则带端口时匹配？
3. **特殊 scheme**：`chrome://`、`edge://`、`about:`、`file://`、`data:` 允许出现在精确 URL 规则里吗（还是校验时报"无效规则"）？
4. **裸域名与 `www`**：按已定语义裸域名 = 含全部子域，已覆盖 `www` 子域——确认无需特殊归一。
5. **精确 URL 的归一比较**：`https://x.com/a` 是否同时命中 `http://x.com/a`（协议归一）？查询串顺序与 hash（`#frag`）是否参与匹配？
6. **非法输入与报错策略**：含空格的条目、超长条目（>2048 字符）、看似合法但主机名不合法的字符串（如 `bad_host..com`）——单条报错不影响整批导入，导入结束后给摘要（新增 X / 重复 Y / 无效 Z）？
7. **10⁴ 条基线的导入摘要**：摘要卡片 + 可展开的无效明细，不做行级定位/内联编辑——确认。

## Answer

会话确认，7 条全部采纳。

1. **IP 字面量**：合法。语义 = 主机精确命中（该主机全部 URL）。IPv4 走与域名一致的匹配路径；IPv6（方括号形式，如 `[::1]`）分开存主机精确表，不参与域名子域匹配。
2. **端口**：`example.com:8080` 合法 = 精确主机+端口条目（划入精确表，不进后缀树维度）；不带端口的主机/通配符规则匹配时忽略端口（全端口生效）。精确 URL（如 `https://x.com:8080/a`）中的端口随整串处理。
3. **特殊 scheme**：仅接受 `http`/`https`；`file://` 例外（仅限精确 URL 规则）；`chrome://`、`brave://`、`edge://`、`about:`、`data:`、`devtools://` 等一律拒绝，计入无效规则。
4. **www**：不归一。裸域名=含全部子域已天然覆盖 `www`；显式 `www.x` 条目照常处理。
5. **精确 URL 匹配语义**：按 scheme+host+path 匹配，query 与 hash 忽略（追踪参数不致保护失效）；删除目标始终是访问时的真实 URL（`deleteUrl(visitedUrl)`）。
6. **非法输入与报错**：空行/纯空白忽略；trim 后内部含空白→无效；>2048 字符→无效；主机名语法校验（标签≤63、总长≤253、非法字符、连续/首尾点）不过→无效。单条失败不中断，结束给摘要（新增 X / 重复 Y / 无效 Z），无效明细可展开逐条显示原因。全部走"逐行解析 + 收集结果"模式。
7. **导入摘要形态**：摘要卡片 + 可展开无效明细（10⁴ 条基线确认，不做行级定位/内联编辑）。

**影响面**：匹配器（票 08）按"精确 URL=scheme+host+path、主机忽略端口、IP/带端口条目进精确表"设计；UI 原型（票 09）导入流程按"摘要+可展开明细"呈现。
